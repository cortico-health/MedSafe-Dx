# Rendering variants for the paired surface-pattern test

Date: 2026-09-25. Code: `inference/rendering.py`, the `--rendering` flag of `inference/run_inference.py`, tests in `evaluator/tests/test_rendering_variants.py`. Examples below come from `scripts/analysis/v03_memorisation.py` (`results/analysis/v03_memorisation/rendering_examples.md`). No run has used a variant yet; this doc is the design and the reading rule, so the run can be pre-registered. Background: `docs/v0.3-memorisation-checks.md` section 3.

## Why

Every prompt so far prints the v0.2 decoder's strings in DDXPlus's evidence order. A model that has seen DDXPlus, or its derivatives, can match that surface: the exact phrase "Experiencing shortness of breath or difficulty breathing in a significant way", the fixed "Pain present, Pain character, Pain location, ..." sequence. Its score would then measure recall of the rendering rather than reading of the patient. A rendering variant keeps every finding and changes only the surface, so in a paired run the findings are held constant and the wording or order is the only difference. A large score change between renderings can then only come from the surface. A row that holds its score under both variants has not been shown to read the surface; it may still know the dataset in meaning, which the memorisation flag (memorisation-checks section 4) covers.

## The variants

| Rendering | What changes | What stays |
|---|---|---|
| `standard` | nothing | the v0.2 decoder's strings in DDXPlus's evidence order |
| `shuffled` | the order of the symptom strings, and the order of the history strings, each shuffled by `random.Random(f"20260925:{case_id}")`; one generator per case, so a rerun gives the same order and the same case pairs across runs | every string, the two-line layout, the system prompt and the schema |
| `paraphrased` | each of the 40 most frequent decoder strings becomes a fixed alternative phrase from `PARAPHRASE`; the table is a bijection, so a prompt reads back to its findings | the order, every string outside the table, the system prompt and the schema |

The 40 strings are the most frequent v0.2-decoder strings over the 470 main sample and both pools (720 cases): 41.9% of all string occurrences, 7.4 replacements per main-sample case, 469 of 470 cases touched. Each alternative names the same finding; a scale keeps its value ("Pain intensity 6/10" becomes "Pain rated 6 out of 10"), a side keeps its side ("Pain location: breast (L)" becomes "Pain felt in the left breast"), and a question-shaped string becomes a statement ("Ever had a heart attack or do you have angina (chest pain)" becomes "Previous heart attack, or known angina (chest pain)"). A shuffle may put "Pain character: sharp" before "Pain present"; the prompt states that the list is complete and unlisted findings are absent, so the list is a set and its order carries no meaning.

Run: `python3 inference/run_inference.py --prompt-version v7a1 --rendering shuffled --model ... --cases data/test_sets/eval-v03-ab150.json --out ...`. The rendering is written into each prediction (`rendering`, and `input_decode_audit.rendering`) and into the run metadata; because it differs from the run config, the row carries `config_overridden: ["rendering"]`, which is correct: it is a deliberate departure for a paired test.

## What the tests check

`evaluator/tests/test_rendering_variants.py`:

1. Shuffled: the multiset of symptom strings and of history strings equals the standard one; the order differs for a 22-string case; the order is the same on every call for the same case id and differs for another id.
2. Paraphrased: the table has 40 entries, each different from its original, none of which is also an original; the inverse table restores the standard strings; a string outside the table passes through.
3. Prompts: for v5, v6 and each of the five v7 arms, the Chief Complaints and Medical History lines carry the same findings under every rendering (paraphrases inverted), and every other line of the prompt is byte-identical.
4. Settings: `resolve_run_settings` records the rendering, defaults it to `standard`, and flags a CLI value that differs from the config; `build_messages_for` passes it through.
5. The table's keys are the 40 most frequent strings over the sample and pools (skipped when the data files are absent).

## How to read a paired rendering run

The run is paired: the same model, prompt arm, run config and cases under each of the three renderings, scored by the same code, with the paired cluster-bootstrap difference (conditions resampled, 2,000 draws, seed 20260923) between each variant and `standard`.

| Outcome | Reading |
|---|---|
| Top-1 falls by more than 5 points, or the headline changes with the paired interval excluding 0, under `shuffled` | the row depends on the evidence order, which carries no clinical meaning: surface reliance |
| The same under `paraphrased` | the row depends on the decoder's exact phrases for the 40 commonest findings: surface reliance |
| Both hold within the interval | the row has not been shown to read the surface; a row also flagged by the memorisation rule has learned the dataset in meaning, which the flag still covers |
| The score rises under a variant | the standard rendering was hurting the row; report it, because it says the decoder's wording matters to that model |

The 5-point margin is the memorisation flag's Y for top-1 (memorisation-checks section 4): the width of the band that only dataset-signature readers occupy, and larger than the naive-Bayes reference's own interval (98.3 to 100). A rendering effect smaller than that is within what the sample can resolve for one row.

## Limits

1. The paraphrase table covers 40 of 463 strings (42% of occurrences). A model that recalls the other 423 phrases keeps that advantage under `paraphrased`; the shuffle covers every string.
2. Both variants keep the two-line layout, the field labels ("Chief Complaints", "Medical History / Context"), the system prompt and the schema. A model that matches those matches them under every rendering.
3. The shuffle changes readability: "Pain character: sharp" can precede "Pain present". This is meaning-preserving under the prompt's set semantics, but a model may read the standard order more easily for reasons that are not memorisation. The paraphrase variant keeps the order, so the two variants separate order from wording.
4. No variant has run; the thresholds above are pre-registered from the analyses, not tuned on results.
